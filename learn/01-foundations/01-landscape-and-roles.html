01. The AI/ML/DL Landscape & Roles

🎯 Learning Outcomes

  • Define the hierarchy and boundaries between AI, Machine Learning, Deep Learning, and Generative AI.
  • Contrast the technical responsibilities of Data Scientists, Machine Learning Engineers, MLOps Engineers, and AI Application Developers.
  • Identify where production code requirements diverge from exploratory research notebooks.

Why It Matters

The AI industry is prone to terminology overlap. A clear understanding of technology boundaries prevents architectural missteps—such as building a complex deep learning model when a simple heuristic or linear regression is appropriate. Furthermore, clarity on industry roles helps developers target high-impact skills that align with real-world engineering teams.

Taxonomy Hierarchy

Artificial Intelligence is the broad umbrella covering any system that mimics human intelligence. Machine Learning is a subset focused on learning patterns from data without explicit rules. Deep Learning uses multi-layered neural networks for unstructured data (vision, text, audio). Generative AI represents deep learning architectures capable of producing novel content.

Worked Exercise

Scenario: You are designing an automated customer support system that must route incoming tickets within 50ms while maintaining 90%+ accuracy. Which role and paradigm combination should lead this solution design?

Show Solution

Answer: An ML Engineer leading a Classical ML or distilled Deep Learning approach (such as TF-IDF + Gradient Boosted Decision Trees or a small DistilBERT model optimized via ONNX). An LLM API call typically exceeds 500ms, making it unsuitable for a 50ms SLA without stream-caching.

⚠️ Common Mistake

Using complex Deep Learning or LLM APIs for structured tabular business problems where XGBoost provides faster execution, better explainability, and superior accuracy.

🚀 Production Tip

Always build a simple linear baseline model first. Measure its performance and latency SLAs before introducing neural networks or GenAI services.
